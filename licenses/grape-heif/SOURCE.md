# grape-heif

Grape converts HEIC and AVIF on Windows with `grape-heif.exe`, a small program of Grape's own (`tools/grape-heif`) built on libheif. It decodes HEIC with libde265 and AVIF with dav1d, and encodes HEIC with x265 and AVIF with libaom (its encoder only). Grape runs it as `grape-heif.exe --grape-heif-worker` for one image at a time, in a Job Object, and talks to it over pipes; pixels go through a temp folder (`crates/grape-heif-proto`). It ships as a separate program next to `Grape.exe`. DECISIONS D33 (HEIC) and D41 (AVIF) have why and how. On macOS Grape uses ImageIO, and for AVIF output its own worker (D41), instead, so the Mac build has no grape-heif.

- **Version:** `1.23.7-grape.2`: libheif's version, then Grape's build number, which goes up with every change to the build. Its banner (`grape-heif.exe -hide_banner -version`) reads:
  ```
  grape-heif version 1.23.7-grape.2 Copyright (c) 2026 the Grape contributors
  configuration: libheif=1.23.7 libde265=1.1.3 x265=4.3 dav1d=1.5.4 aom=3.15.2 plugins=disabled crt=static protocol=2
  license: GPL-3.0-or-later (libheif and libde265 LGPL-3.0-or-later, x265 GPL-2.0-or-later, dav1d and aom BSD-2-Clause)
  ```
- **License:** **GPL-3.0-or-later** as a whole (`LICENSE.txt`). It links libheif and libde265 (LGPL-3.0-or-later), x265 (GPL-2.0-or-later), and dav1d and libaom (BSD-2-Clause, with small parts under BSD-3-Clause, MIT and ISC) statically; all of them combine under GPL-3.0. Grape's own source in it (`tools/grape-heif`, `crates/grape-heif-proto`) is MIT, like the rest of Grape. Because of the GPL, it only ever ships as this separate executable, never inside Grape's own binaries (golden rule 6, ENGINES.md licensing rule 2).
- **AV1 patents:** dav1d and libaom each come with the Alliance for Open Media Patent License 1.0, a royalty-free license to the AV1 patents of AOM's members. Its section 1.2.1(b) asks that a binary distribution reproduce it in its legal notices, so each project's own copy ships here (`dav1d-PATENTS.txt`, and the `PATENTS` part of `aom.txt`); the two differ only in their quotation marks and a typo.

## The exact source

Every build comes with its complete corresponding source, `grape-heif-1.23.7-grape.2-source.tar.gz`: CI's `grape-heif` job makes it in the same run as the installer (DECISIONS D33), and it's in that run's artifacts (`grape-heif-source`) and on the GitHub Release that ships the installer. It holds:

- `grape-heif/`: Grape's source for the program (`tools/grape-heif`, `crates/grape-heif-proto`, `licenses/grape-heif`, `LICENSE`) at the commit that was built;
- `vendor/`: every Rust crate in `tools/grape-heif/Cargo.lock` (`cargo vendor`);
- `vcpkg-downloads/`: the five source archives below, with `SHA512SUMS`;
- `vcpkg-ports/`: vcpkg's `libheif` and `aom` ports (the bases of Grape's overlays), its `libde265`, `x265`, `dav1d`, `vcpkg-cmake`, `vcpkg-cmake-config`, `vcpkg-tool-meson` and `vcpkg-cmake-get-vars` ports and the `x64-windows-static` triplet at the pinned commit, and Grape's two overlay ports in `overlay/libheif` and `overlay/aom`;
- `BUILD.md`: the commands, the Visual Studio, compiler, CMake, NASM, ninja, Perl, Python, meson and Rust versions of the run, and the SHA-256 of the `grape-heif.exe` it made.

libde265, x265 and dav1d are built by vcpkg's own ports at that commit, with their patches, unchanged. libheif is built by Grape's overlay port, `tools/grape-heif/vcpkg/ports/libheif`: the commit's libheif 1.23.5 recipe with these changes only:

- the version is 1.23.7, and the source is the release asset above, fetched with `vcpkg_download_distfile`, so the archive that's built is the one in the source bundle (the recipe fetched GitHub's archive of the tag);
- `-DENABLE_PLUGIN_LOADING=OFF`: libheif never loads a plugin DLL, even with `LIBHEIF_PLUGIN_PATH` set (the banner's `plugins=disabled` is libheif's own answer), so every codec is built in;
- a `dav1d` feature (`WITH_DAV1D`, with dav1d as its dependency), which the recipe doesn't have (it turns dav1d off), so AVIF decodes with dav1d;
- `-DWITH_AOM_DECODER=OFF`, and the `aom` feature turns on libaom's encoder only (`WITH_AOM_ENCODER`; the recipe's feature turned on both): dav1d is the only AV1 decoder, and libaom's decoder, though compiled into libaom, is never referenced, so it isn't in the program;
- `-DWITH_FFMPEG_DECODER=OFF` and `-DWITH_FUZZERS=OFF`: nothing of either is built;
- `license` in `vcpkg.json` reads `LGPL-3.0-or-later AND MIT`, as libheif's own headers say.

The four patches and `cmake-project-include.cmake` are the commit's, byte for byte.

libaom is built by Grape's second overlay port, `tools/grape-heif/vcpkg/ports/aom`: the commit's libaom 3.15.1 recipe taken to 3.15.2 (its fixes are all in the encoder: one for still pictures, two that OSS-Fuzz found, and two more), with one change: the source is the release tarball above, fetched with `vcpkg_download_distfile` and checked by its SHA-512. The recipe fetched the tag with git and made its own archive, which has no hash to check and whose bytes depend on the git that made it. Its patch (`aom-rename-static.diff`), its options and its copyright list are the commit's, byte for byte.

### How it's built

On Windows, with Visual Studio's C++ tools, git and Rust 1.99. CI builds on GitHub's `windows-latest` image, which has Visual Studio 2026; each build's `BUILDINFO.txt`, and the source bundle's `BUILD.md`, name the Visual Studio and `cl.exe` it used, and the build tools vcpkg fetched at the pinned commit (CMake, NASM, ninja, and Strawberry Perl for libaom, Python and meson for dav1d):

```
.\tools\grape-heif\build.ps1 -VcpkgRoot <an empty folder>
```

It clones vcpkg at the pinned commit, bootstraps it, fetches and checks the sources, runs `vcpkg install libheif[core,hevc,aom,dav1d]:x64-windows-static --overlay-ports=tools\grape-heif\vcpkg\ports`, then `cargo build --release --locked --bins` in `tools\grape-heif` with `VCPKG_ROOT` set (`.cargo/config.toml` turns on `+crt-static`). The program is `tools\grape-heif\target\release\grape-heif.exe`. From the source bundle, the same steps work offline but for the build tools, which vcpkg fetches and checks by SHA-512: `BUILD.md` says how to point vcpkg at `vcpkg-downloads/` and cargo at `vendor/`.
