# grape-heif

Grape converts HEIC on Windows with `grape-heif.exe`, a small program of Grape's own (`tools/grape-heif`) that decodes with libheif and libde265 and encodes with libheif and x265. Grape runs it as `grape-heif.exe --grape-heif-worker` for one image at a time, in a Job Object, and talks to it over pipes; pixels go through a temp folder (`crates/grape-heif-proto`). It ships as a separate program next to `Grape.exe`. DECISIONS D33 has why and how. On macOS Grape uses ImageIO instead, so the Mac build has no grape-heif.

- **Version:** `1.23.7-grape.1`: libheif's version, then Grape's build number, which goes up with every change to the build. Its banner (`grape-heif.exe -hide_banner -version`) reads:
  ```
  grape-heif version 1.23.7-grape.1 Copyright (c) 2026 the Grape contributors
  configuration: libheif=1.23.7 libde265=1.1.3 x265=4.3 plugins=disabled crt=static protocol=1
  license: GPL-3.0-or-later (libheif and libde265 LGPL-3.0-or-later, x265 GPL-2.0-or-later)
  ```
- **License:** **GPL-3.0-or-later** as a whole (`LICENSE.txt`). It links libheif and libde265 (LGPL-3.0-or-later) and x265 (GPL-2.0-or-later) statically; GPL-2.0-or-later and LGPL-3.0-or-later combine under GPL-3.0. Grape's own source in it (`tools/grape-heif`, `crates/grape-heif-proto`) is MIT, like the rest of Grape. Because of the GPL, it only ever ships as this separate executable, never inside Grape's own binaries (golden rule 6, ENGINES.md licensing rule 2).

## The exact source

Every build comes with its complete corresponding source, `grape-heif-1.23.7-grape.1-source.tar.gz`: CI's `grape-heif` job makes it in the same run as the installer (DECISIONS D33), and it's in that run's artifacts (`grape-heif-source`) and on the GitHub Release that ships the installer. It holds:

- `grape-heif/`: Grape's source for the program (`tools/grape-heif`, `crates/grape-heif-proto`, `licenses/grape-heif`, `LICENSE`) at the commit that was built;
- `vendor/`: every Rust crate in `tools/grape-heif/Cargo.lock` (`cargo vendor`);
- `vcpkg-downloads/`: the three source archives below, with `SHA512SUMS`;
- `vcpkg-ports/`: vcpkg's `libde265`, `x265`, `vcpkg-cmake` and `vcpkg-cmake-config` ports and the `x64-windows-static` triplet at the pinned commit, and Grape's libheif overlay port;
- `BUILD.md`: the commands, the Visual Studio, compiler, CMake, NASM and Rust versions of the run, and the SHA-256 of the `grape-heif.exe` it made.

### The libraries

They're built by [vcpkg](https://github.com/microsoft/vcpkg) at commit `e456309491fd875487bf02b8a0dca76c1b1b00cc` (2026-10-10), triplet `x64-windows-static` (static libraries, static C runtime), as `libheif[core,hevc]`. `tools/grape-heif/vcpkg.lock.json` pins all of this, and `tools/grape-heif/build.ps1` checks each archive's SHA-512 against it and against the port that fetches it before anything is built.

libde265 and x265 are built by vcpkg's own ports at that commit, with their patches, unchanged. libheif is built by Grape's overlay port, `tools/grape-heif/vcpkg/ports/libheif`: the commit's libheif 1.23.5 recipe with these changes only:

- the version is 1.23.7, and the source is the release asset above, fetched with `vcpkg_download_distfile`, so the archive that's built is the one in the source bundle (the recipe fetched GitHub's archive of the tag);
- `-DENABLE_PLUGIN_LOADING=OFF`: libheif never loads a plugin DLL, even with `LIBHEIF_PLUGIN_PATH` set (the banner's `plugins=disabled` is libheif's own answer);
- `-DWITH_FFMPEG_DECODER=OFF` and `-DWITH_FUZZERS=OFF`: nothing of either is built;
- `license` in `vcpkg.json` reads `LGPL-3.0-or-later AND MIT`, as libheif's own headers say.

The four patches and `cmake-project-include.cmake` are the commit's, byte for byte.

### How it's built

On Windows, with Visual Studio's C++ tools, git and Rust 1.99. CI builds on GitHub's `windows-latest` image, which has Visual Studio 2026; each build's `BUILDINFO.txt`, and the source bundle's `BUILD.md`, name the Visual Studio and `cl.exe` it used:

```
.\tools\grape-heif\build.ps1 -VcpkgRoot <an empty folder>
```

It clones vcpkg at the pinned commit, bootstraps it, fetches and checks the sources, runs `vcpkg install libheif[core,hevc]:x64-windows-static --overlay-ports=tools\grape-heif\vcpkg\ports`, then `cargo build --release --locked --bins` in `tools\grape-heif` with `VCPKG_ROOT` set (`.cargo/config.toml` turns on `+crt-static`). The program is `tools\grape-heif\target\release\grape-heif.exe`. From the source bundle, the same steps work offline: `BUILD.md` says how to point vcpkg at `vcpkg-downloads/` and cargo at `vendor/`.
