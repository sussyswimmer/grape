# grape-platform

OS glue: drag detection, modifier and cursor state, display bounds, file actions and haptics. **Lane A (Claude Code) owns this crate.** This is the riskiest code in Grape. Read `docs/PLATFORM_MACOS.md` or `docs/PLATFORM_WINDOWS.md` before changing anything here.

Windows came first (DECISIONS D8). The macOS port (D18) is real code now: drag polling, display bounds, the overlay window, file actions and haptics. Other hosts (Linux dev machines and CI) get `unsupported.rs`, where everything returns `Err(PlatformError::Unsupported)`.

## Hard rules
- **Never block the user's input.** Hook callbacks and pasteboard polls do almost nothing: they read state, send it on a bounded channel and return. On Windows, a slow `WH_MOUSE_LL` callback gets the hook silently removed by the OS.
- **No permissions prompts on macOS** (DECISIONS D7). Don't add `NSEvent` *key* monitors or `CGEventTap`, which require Accessibility.
- **Coordinates out of this crate are global, top-left origin, y down.** Physical pixels on Windows. Points on macOS, with the origin at the top-left of the primary (menu-bar) screen, and `DisplayBounds::scale` is always 1.0 there. Cocoa (`mouseLocation`, `NSScreen` frames, `setFrame:`) is bottom-left origin, so convert here, once, with the helpers in `mac_rules.rs`.
- **macOS windows.** The overlay is hardened as `WindowRole::Overlay` (level 101) and the toast as `WindowRole::Toast` (100), so an open wheel always covers the toast; never put the toast at or above the overlay's level, or a progress update ends the drag over the wheel. Neither window becomes key because of `"focusable": false` in `tauri.conf.json`. The tool panel is `WindowRole::Panel` (99), under both, and it's the one hardened window Grape makes key: `show_panel` makes it key and asks to activate Grape, `hide_panel` hands activation back (D31). The float shelf is `WindowRole::Shelf` (3), under all three: `show_shelf` never makes it key or activates Grape (only a click does), `hide_shelf` hands activation back to the app the user was last in (`follow_app_activations`, not the app in front at the show: the shelf stays open across app switches), and `harden_window` gives it the `Closable` bit (never tao's `set_closable`) so Cmd+W is a close request (D43). `harden_window` turns `canHide` off for all four, so the default menu's Hide (Cmd+H) leaves them on screen and they still show while Grape is hidden; the app calls `unhide_app` before it shows Settings, the one window Hide hides. Never `NSApp.hide` or tao's `set_focus`.
- **macOS drags.** A file drag session starts the drag at once (`DragTracker::start_now`): AppKit already applied its threshold. The keys held when the poller first sees that session are the baseline, as on Windows. The drag thread holds an `NSProcessInfo` activity for its whole life (App Nap) and waits with `park_timeout`, which `stop` cuts short.
- **macOS Move.** A mounted volume's root (its own `lstat` device isn't its folder's) never moves and isn't counted as moved or unsure. Each item is judged (`mac_rules::judge_move`) from a snapshot taken right after its own move, before the next item moves. Grape activates itself for the panel and alert, then hands activation back to the app that was in front; never `NSApp.hide`. Share does the same through an AirDrop delegate (`ShareDone`), kept alive with its service until AirDrop reports back, and only once no AirDrop window is key. Settings' `pick_folder` shares Move's panel but neither activates nor hands back: the Settings window is already key.
- **macOS threads.** `NSScreen`, `NSWindow`, `NSOpenPanel` and `NSAlert` are main-thread only (`MainThreadMarker`). Main-thread UI from a worker goes through `dispatch2::run_on_main`, which waits: never call it from a thread the main thread is waiting for. Tauri's `ns_window()` pointer is only good on the main thread until the autorelease pool drains, so retain it at once. Wrap AppKit work on Grape's own threads in `autoreleasepool`.
- **The image helper worker (D33, D41).** `macos::heif` and `avif` run only in the worker process (`Grape --grape-heif-worker`, or the test bin), never in Grape's own: a crash in ImageIO, or a rav1e encode that can't be cancelled, must end one job, not the tray and the drag. `avif-encode` (rav1e, BSD-2-Clause, plus the AOM Patent License in the notices) is on only in the app's macOS build: never turn it on for Windows or Linux builds of the app. rav1e's arm64 assembly is on only for aarch64-apple-darwin (its build script compiles `src/arm/64/*.S` with `cc`); the Intel slice is pure Rust. `CGImageSourceSetAllowableTypes` restricts ImageIO for the whole process, so it's called only there, first thing and on one thread (`ImageIo::restrict_process`, from `main.rs` and the test bin; never from the codec's calls, which tests run on many threads), and only through `dlsym`: never the objc2-image-io binding, whose import would stop Grape from launching on macOS 13 (CI's DMG job checks `nm -um`). No failure detail holds a path, and the codec logs nothing.
- Every `unsafe` block gets a `// SAFETY:` comment.
- **Logging** (`log`) is only for saying why an action did something other than what was asked (Terminal opening another app than the one picked), for the Windows share sheet's HRESULTs and the drag-out watchdog, which only a run on a real PC can check, and for the Mac drag out's stale-drag and unexpected-operation lines (and a source that never reported its end), which only a Mac can check. Never log a path or a file name.
- Gate code with `#[cfg(target_os = "macos")]` / `"windows"`. Both must compile in CI even if you only tested one. From Linux, check the Mac target with `CC_aarch64_apple_darwin=clang AR_aarch64_apple_darwin=llvm-ar-18 CFLAGS_aarch64_apple_darwin="--target=arm64-apple-macos11" cargo clippy -p grape-platform --features avif-encode --all-targets --target aarch64-apple-darwin -- -D warnings` (the env also lets rav1e's build script assemble its arm64 files). The Intel Mac target needs `CC_x86_64_apple_darwin=clang AR_x86_64_apple_darwin=llvm-ar-18 CFLAGS_x86_64_apple_darwin="--target=x86_64-apple-macos10.13"` for objc2's exception helper.
- Tests never open a panel, an alert, AirDrop or the share sheet, never start a real drag, and never call `run_on_main` (nothing serves the main queue under `cargo test`). On Windows a test may only reach code that returns before `ShowShareUIForWindow` or `SHDoDragDrop`: nothing left to share, or the button already up. On macOS a test may only reach code that returns before `beginDraggingSession`: nothing to drag, the button up (through `drag_with`'s seam), or a null window.

## When you finish a change here
- State which OS you actually ran it on.
- Add or refresh the matching manual QA lines in `docs/TESTING.md`.
- Windows changes near drop handling: re-run "Shift-drop never deletes the source" by hand.
